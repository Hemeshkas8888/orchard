# iPad mini 2 Cellular (J86): Linux RAM bring-up report

This report records experiments by Perry Raskin on one **iPad4,5 / J86AP**
(Apple A7/S5L8960X, CPID `0x8960`, BDID `0x0c`) through 1 November 2026.
It is not an Orchard device profile or an installation procedure. J85
(`iPad4,4`, Wi-Fi) is a different board; see its [separate report](j85.md).
Neither board's calibration, GPIO or charger settings should be substituted
for the other's.

## Sources and test environment

The public source companion is
[perryraskin/ipad-mini2-omarchy at bf6637c](https://github.com/perryraskin/ipad-mini2-omarchy/tree/bf6637c8e8a679164847493e96ce99ca9627f326).
The initial RAM desktop used the Pomme v0.1.0 boot components, Hoolock Linux
7.0.12 at `dfa4d42081312dd34ec33ee8d23174309f683188`, 4 KiB pages and
Omarchy A 0.1.1 with Labwc software rendering and Quickshell. Later Wi-Fi
and isolated audio tests used the custom `7.0.12-j86-audio2` RAM kernel.

These observations come from several experimental builds and sessions, not
one integrated release. The source companion includes later changes that
have only host tests. Publishing a checkpoint does not qualify every file
in it on hardware. In particular, none of these results validates Orchard
main's kernel, firmware converter, recovery, CLI or installer on J86.

The desktop's base root is a read-only Mac-hosted ext4 image served over USB
NBD; its runtime and home are in RAM. A separate writable Mac-hosted image
holds installed applications. The Mac and cable remain necessary. No iPad
internal-storage installation or partition modification was performed.

## Observed on the device

| Area | Observation | Limit |
| --- | --- | --- |
| Boot and display | DFU/checkm8, PongoOS and m1n1 booted AArch64 Linux into RAM; a 1536 × 2048 software-rendered Omarchy desktop ran with 2× scaling. USB serial and network shells worked. | This is a tethered experiment, not a clean Orchard build or an installed system. GPU acceleration is unqualified. |
| Touch and buttons | The exact-board native N1 module produced aligned physical app taps; stop/restart was exercised. Home opened the menu. Brightness, dragging, long-press menus, screen-off/wake and the held-Power menu were owner-confirmed. | Firmware and panel calibration are private inputs. The complete four-orientation and restart cycle remains unfinished; screen-off is not SoC suspend. |
| Wi-Fi | The internal USB Broadcom device enumerated as `0a5c:bd1c`, identified as BCM4324 revision 6, and reached association, DHCP, DNS and direct HTTPS on the audio2 kernel. Combined touch use was owner-confirmed. | Exact-board firmware/NVRAM remain private. Long-duration coexistence, disable/recovery, channel coverage and suspend/reconnect are unqualified. |
| Mac-backed applications | Signed package installation and bounded 16 MiB fsync/readback, clean detach, offline filesystem checks and remount persistence passed on the separate app image. | This does not demonstrate internal iPad storage access or qualify every candidate storage profile. |
| Native speaker audio | A bounded two-second 500 Hz ALSA tone was physically heard. The public `a8c6a0e` PCM revision passed isolated prepare-close, drain/drop/restart and ten-second muted playback; a later volume test was heard becoming louder. | These are isolated, bounded results. Acoustic mute/channel separation, physical volume keys, sustained playback and desktop/touch/Wi-Fi coexistence remain unqualified. |
| App audio plumbing | Headless PipeWire/WirePlumber tests passed silent transfers through `pw-play` and `paplay`, multiple formats, interruption, mixed clients and service restart. | Silent transfers do not establish audible app playback. This was not an integrated desktop audio test. |

The records retain earlier failures and subsequently corrected claims. Audio
bring-up encountered STOP protocol failures and an unresponsive experimental
boot. The later bounded `a8c6a0e` tests passed, but the checkpoint's additional
queued-worker STOP race fix is host-tested only; it was not loaded into that
healthy session. A successful build or silent DMA transfer is not evidence
of stable speaker playback or recovery.

Bluetooth, HDMI, automatic rotation, GPU acceleration, battery reporting,
charging policy and true system suspend remain unqualified. No cellular-modem
support is claimed by testing the Cellular model.

## Follow-up for Orchard

A useful first implementation would port the exact J86 description, firmware
preparation and native touch support to Orchard's current `apple-4k` kernel
and device layers, with a reproducible RAM-boot recipe. The companion's
experimental overlays and fixed-board modules need review and adaptation;
they are not ready-made patches for Orchard main. The ALSA/SIO work also
derives from Orchard components, so its provenance and changes need to stay
explicit when ported back.

Build from a clean checkout, then test that exact Orchard revision on J86
before marking any feature working. Keep Wi-Fi and audio follow-ups scoped
to their shared-controller ownership and recovery requirements. Desktop and
distribution changes belong in omarchy-a rather than the hardware report.

Public contributions should contain code, recipes and summarized evidence,
not Apple firmware, NVRAM/calibration, captured device trees, credentials,
identifying logs or private boot bundles. The owner-side extraction gates
and matching-board checks must remain part of any reproducible recipe.
